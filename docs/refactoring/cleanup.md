# Unused-file cleanup

Follow-up to the role-based refactor. This cleanup removes files that have no
remaining route, application, component namespace, template or asset dependency.
The live marketplace, Seller Center, logistics workspace and admin interface
retain their existing routes and navigation markup.

## Removed

381 files were removed from the working tree:

- 69 unused Blade templates: buyer/seller legacy copies, starter welcome pages,
  the old logistics landing screen, duplicate logistics components/pagination,
  unused layouts, and an unused pager/session-status component.
- 17 unreferenced public assets belonging to those removed templates and static
  prototypes.
- Four unrouted controllers: the older buyer web auth and buyer API seller
  handlers, and the older seller auth and Seller Center handlers.
- 13 root debug/account-repair scripts (`check_*`, `test_*`, `update_pwd*`,
  `create_logistics_user.php`, `create_migration.php`). None was executed.
- Both standalone `index.html` prototypes. Laravel's `public/index.php` and
  routed buyer landing page remain the web entry points.
- The empty `post_response.html`, generated root `server.log`, outdated
  `README-init.md`, and placeholder `tests/Unit/ExampleTest.php`.
- 270 generated design-inspection files under `.taste-skill/` and two PHPUnit
  cache files. These directories can be regenerated by their tools.

The empty Unit test-suite entries were removed from both PHPUnit configurations.
The feature tests, including the home-page smoke test, remain. Historical audits
now note that their temporary screenshot/report artifacts were cleaned up.

## Kept and reorganized

Three scripts still used by active seller pages were moved before removing
their old legacy folders:

| Before | After |
| --- | --- |
| `public/assets/seller/js/legacy/pages/products/create.js` | `public/assets/seller/js/products/create.js` |
| `public/assets/seller/js/legacy/pages/reports/index.js` | `public/assets/seller/js/reports/index.js` |
| `public/assets/seller/js/legacy/pages/vouchers/index.js` | `public/assets/seller/js/vouchers/index.js` |

Template references were updated. The shared sidebar and navbar files retain
their active buyer, seller, logistics and admin sections; ten unused navigation
variants were removed. The logistics route named `logistics.landing` remains
and continues redirecting through `CentralEntryController` as before.

`README.md` now describes the actual application and current setup, replacing
the default Laravel marketing readme. `README-INTEGRATED.md` remains the account
and authorization reference. `run.txt` is unchanged.

Installed dependencies (`vendor/`, `node_modules/`), the production asset build,
`.env`, uploads, application storage, migrations, factories, seeders, configuration,
regression tests, developer tooling and agent settings were retained. Generated
inspection output and root server logs are ignored by Git for future runs.

## Recovery

Automatic approval review initially rejected an irreversible bulk deletion.
Before retrying, every removal target was archived and each archived file was
verified against its SHA-256 hash. The approved cleanup retained this recovery
archive outside the web document root:

`storage/framework/cleanup-recovery-de1128122b5c4d6291d6ae3ae9f4751b.zip`

The archive contains all 381 removed files at their original relative paths.
It is ignored by Git and is not needed to run the application. The compressed
archive uses about 17.7 MiB; removed working-tree files totaled about 20.8 MiB.
Extract it to a separate review directory to inspect or recover individual files.

## Validation

- All 415 route definitions match the pre-cleanup snapshot, including actions and middleware.
- OK (45 tests, 1009 assertions): `ViewStructureTest`, `BuyerWebShoppingTest`, and `CommerceRegressionTest`.
- `npm run build` passes.
- All surviving Blade templates compile, and static structural checks verify
  includes, shared component registration, external asset paths and server data.
- Composer's optimized autoloader was regenerated after removing unused classes.
- Eight representative requests rendered successfully with the correct role
  navigation: landing/login, buyer shop/help, seller dashboard/product creation,
  admin dashboard and logistics dashboard. The database transaction was rolled
  back after these checks.

The previously reported full-suite database configuration limitations remain;
no database credentials, grants or application data were changed.
