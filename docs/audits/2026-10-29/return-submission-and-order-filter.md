# Return submission, seller visibility and Orders filter — 29 October 2026

The local database still contained zero return requests when this task began.
Found and reproduced a real submission mismatch: mobile permitted optional
details such as `broken`, but the API required ten characters for every reason.
The old dialog closed before the POST finished, so validation/network failures
lost the visible form and left the seller with no saved request.

## Changes

- Buyer API return validation accepts short optional details for predefined
  reasons. Other still requires at least ten characters, and the 300-character
  limit remains. Buyer ownership, delivered-order eligibility, return window,
  variation identity, remaining quantity and discounted refund calculations are
  unchanged. A repeated open request returns that buyer's existing case with
  HTTP 409 so a retry after a lost response can recover it safely.
- A successful submission creates an unread `return_requested` notification
  for the exact selling **user ID**, in the same transaction. No seller-record
  ID aliases were added and no live ownership data was reassigned.
- Seller notification links lead to Returns & Refunds. The page now exposes a
  seller-scoped JSON refresh response with rendered records, counts and a
  version. Its list refreshes every 15 seconds while visible; an explicit
  Refresh requests link is available. Automatic/manual refresh preserves a
  focused form or an unfinished note, including edits made during a fetch.
  Network failures keep the existing records visible. All/requested/awaiting
  item/refund-recorded counters and the configured return window are shown.
- Seller records show the case ID, purchased product name/variation, quantity,
  reason and amount. The existing approval/rejection/receipt POST actions are
  preserved. Receipt wording accurately says refund recorded; money transfers
  are still arranged separately with the buyer.
- Mobile uses a dedicated OrderReturnDialog. It remains open with all input on
  errors, shows persistent feedback, blocks duplicate sends/dismissal while
  sending, and confirms success only after receiving a saved matching case ID.
  A duplicate response can recover the already-saved case. Quantity is limited
  to purchased units remaining after completed returns.
- Orders pills now read **All, To Ship, In Transit, Delivered, Return,
  Cancelled**. Return shows orders with saved cases, including active, rejected,
  refunded and cancelled return-case history. It combines with the existing
  product-name search. An order's original delivery status is preserved, so
  delivered orders with partial returns can also remain under Delivered.
  Cancelled still filters cancelled **orders**, not cancelled return cases.
- Order cards summarize the return status. Order details show case IDs,
  quantity/amount, seller notes, approval instructions and rejected/refund
  outcomes. Existing API/status filters remain, with `status=return` added and
  `status=all` correctly including all of the authenticated buyer's orders.
